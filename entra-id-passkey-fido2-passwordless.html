Deploying Entra ID Hardware Passkeys (FIDO2) & Conditional Access Authentication Strength Policies

How enterprise security teams eliminate adversary-in-the-middle (AiTM) phishing attacks by enforcing FIDO2 passkeys and CBA across all corporate workloads.

Gunas
Principal Cloud & AI Security Architect

The Need for Phishing-Resistant Authentication

Adversary-in-the-middle (AiTM) phishing toolkits like Evilginx2 allow attackers to proxy login sessions, steal session cookies, and bypass traditional push-notification Multi-Factor Authentication (MFA). **Microsoft Entra ID Passkeys (FIDO2)** bind authentication cryptographically to the specific origin URL, making credential theft impossible.

FIDO2 Security Standard: FIDO2 credentials utilize public-key cryptography (ECC P-256 / RSA 2048) locked inside hardware security chips (TPM / YubiKey), ensuring credentials never leave the hardware device.

Architecture Topology: Entra ID Authentication Strength Enforcement

Figure 1: Evaluating Phishing-Resistant MFA Strength in Entra Conditional Access

1. FIDO2 Security Keys

Hardware keys (YubiKey 5 Series) or Windows Hello for Business provide cryptographic proof of identity without sending passwords over the wire.

2. Authentication Strength Policies

Conditional Access policies enforce "Phishing-resistant MFA" strength, explicitly blocking SMS, phone calls, and standard OTP apps for privileged admins.

3. Temporary Access Pass (TAP)

Time-bound, single-use access passes generated by helpdesk staff to onboard new employees directly into passwordless passkey registration.

4. Certificate-Based Authentication (CBA)

Integrates smart cards and PIV credentials directly with Entra ID without requiring legacy AD FS or on-premises federation servers.

Microsoft Graph PowerShell: Enforcing Phishing-Resistant MFA Strength

The PowerShell script below creates a custom Conditional Access Policy requiring Phishing-Resistant MFA for Global Administrators:

# Connect to Microsoft Graph SDK
Connect-MgGraph -Scopes "Policy.ReadWrite.ConditionalAccess", "Policy.Read.All"

# Retrieve Built-In "Phishing-Resistant MFA" Policy ID
$phishResistantPolicy = Get-MgBetaPolicyAuthenticationStrengthPolicy | Where-Object { $_.DisplayName -eq "Phishing-resistant MFA" }

# Build Conditional Access Conditions
$conditions = @{
    Applications = @{ IncludeApplications = @("All") }
    Users        = @{ IncludeRoles        = @("62e90394-69f5-4237-9190-012177145e10") } # Global Admin Role ID
}

# Define Access Controls (Require Phishing-Resistant MFA)
$controls = @{
    Operator                         = "OR"
    AuthenticationStrengthPolicyId  = $phishResistantPolicy.Id
}

# Create Conditional Access Policy
New-MgBetaConditionalAccessPolicy -DisplayName "CA001: Enforce Phishing-Resistant MFA for Global Admins" `
    -State "Enabled" `
    -Conditions $conditions `
    -GrantControls $controls

Write-Host "Policy CA001 Created Successfully" -ForegroundColor Green
