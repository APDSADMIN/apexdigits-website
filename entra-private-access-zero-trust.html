Deploying Microsoft Entra Private Access: Replacing Legacy VPNs with Zero Trust

A comprehensive blueprint for phasing out legacy perimeter VPNs and implementing identity-centric micro-segmentation with Microsoft Entra Private Access & Global Secure Access.

Gunas
Principal Cloud & AI Security Architect

The Imperative to Eliminate Perimeter VPNs

Traditional virtual private networks (VPNs) grant users full network-level access once authenticated. In a world of sophisticated lateral movement attacks and zero-day vulnerabilities in edge gateway appliances, network-level trust is a liability. Microsoft Entra Private Access (part of Microsoft Security Service Edge - SSE) replaces perimeter gateways with identity-centric, least-privilege application proxying.

Zero Trust Philosophy: Never trust network location. Validate explicitly using identity context, device health, and continuous access evaluation (CAE) before granting access to specific TCP/UDP application endpoints.

Architecture Overview: Global Secure Access (GSA)

Microsoft Entra Private Access routes client traffic securely to internal enterprise apps without exposing public inbound firewall ports. Lightweight Private Access Connectors deployed on internal Windows Servers establish outbound-only TLS 1.3 connections to Microsoft's global edge network.

1. Global Secure Access Client

Runs on Windows 11/10 and macOS endpoints, intercepting private IPv4/IPv6 traffic or FQDN requests and encapsulating them securely via WireGuard-based tunnels.

2. Entra Private Access Edge

Enforces Conditional Access rules, multi-factor authentication (MFA), compliant device checks, and Continuous Access Evaluation (CAE) in real time.

3. Connector Groups

High-availability connector clusters situated inside AWS VPCs, Azure VNets, or on-premises datacenters, acting as local proxies for target applications.

4. App Segments

Granular target definitions specifying exact IP ranges, ports (RDP 3389, SSH 22, SMB 445), or internal domains with least-privilege scoping.

PowerShell Automation: Deploying Connector Groups

Use the following PowerShell script to automatically verify system prerequisites, register Entra Private Access Connectors, and assign Connector Groups via Microsoft Graph PowerShell SDK:

# Install Microsoft Graph Entra Beta module
Install-Module Microsoft.Graph.Beta.Applications -Scope CurrentUser -Force

# Connect with required admin scopes
Connect-MgGraph -Scopes "Application.ReadWrite.All", "NetworkAccess.ReadWrite.All"

# Define New Connector Group Name
$groupName = "Production-VNet-US-East"
$connectorGroup = New-MgBetaNetworkAccessConnectorGroup -Name $groupName -Region "nam"

Write-Host "Created Connector Group ID: $($connectorGroup.Id)" -ForegroundColor Green

# Assign Quick Access Application Segment to Connector Group
$appSegment = Get-MgBetaApplication -Filter "displayName eq 'Internal-RDP-Cluster'"
Update-MgBetaApplication -ApplicationId $appSegment.Id -OnPremisesPublishing @{
    connectorGroupId = $connectorGroup.Id
    externalAuthenticationOption = "passthrough"
}

Write-Host "Successfully attached Connector Group to App Segment!" -ForegroundColor Cyan

Comparing Legacy VPN vs Microsoft Entra Private Access

Capability Legacy Corporate VPN Entra Private Access (Zero Trust)
Network Exposure Full subnet access (10.0.0.0/8) Per-app port/IP micro-segmentation
Inbound Firewall Rules Requires open inbound ports (443 / 1194) Zero inbound open ports (Outbound 443 only)
Authentication Gate At connection initiation only Continuous Access Evaluation (CAE) on every request
MFA & Device Health Static connection challenge Dynamic Entra ID Conditional Access evaluation
SSO & Kerberos Complex domain trust / line-of-sight required Seamless Kerberos Constrained Delegation (KCD) integration

Step-by-Step Migration Strategy

  1. Application Discovery: Run Entra Global Secure Access traffic logs to identify all internal FQDNs, SMB shares, RDP targets, and SSH endpoints currently traversing VPNs.
  2. Group Application Segments: Group discovered targets into logical App Segments based on security tier (e.g., Tier-0 Admin Apps, Finance SMB Shares, Developer SSH Jumpboxes).
  3. Deploy High-Availability Connectors: Install at least 2 Private Access Connectors per availability zone to guarantee 99.99% connector redundancy.
  4. Enforce Strict Conditional Access: Mandate Entra Joined / Compliant Devices, Phishing-Resistant FIDO2/Passkey MFA, and Risk-Based Sign-In policies.
  5. Phase Out VPN Client: Silently uninstall legacy VPN clients via Intune / PowerShell and enable GSA Client auto-start across all endpoints.

Summary

Migrating to Microsoft Entra Private Access converts dangerous perimeter network trusts into granular identity-verified application connections.
